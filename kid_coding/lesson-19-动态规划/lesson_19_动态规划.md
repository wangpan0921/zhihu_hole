# 通关攻略的最优解：动态规划 —— 把贪心翻过车的那一题，老老实实做对

> 这是《我的世界里学编程》系列的第 19 篇，**第三阶段 · 算法关**的第 5 课。**上期回顾**：上一课史蒂夫背着 20 kg 背包面对三箱末影龙矿粉，**贪心**（每一步都挑"每 kg 最贵"）在**可以切散的分数背包**里拿了满分 110；可一换成**不能切的 0-1 背包**——铁矿粉抢了先、金矿粉再也塞不下——贪心当场翻车：**60 分**，而真正的最优是**100 分**。**那 40 分到底去哪了？** **今天**，史蒂夫把那次翻车的教训摊在桌上，请出算法界的"记账高手"——**动态规划（Dynamic Programming,DP）**——翻译成人话：**"我不只看眼前最赚,我把每一种小情况的最优解都记在账本上,大问题就是查几个小账本拼出来"**。信奥赛里一半以上的难题都是 DP,而**0-1 背包**正是打开这扇大门的那把标准钥匙——**今天我们让它老老实实把 100 分交出来**。

## 先猜猜看

老规矩,先别急着往下拉。看这段代码——**屏幕最后会打印几?是上节课贪心翻车的那个 60,是正解 100,还是别的数?**

```python
# 还是上节课那三箱末影矿粉——这次是不能切的 0-1 背包
weights = [10, 20, 30] # 分别表示铁、金、钻石的重量
values  = [60, 100, 120] # 分别表示铁、金、钻石的价值
capacity = 20
n = len(weights)

# ① 建一张"账本":n+1 行、capacity+1 列,每一格先填 0
dp = [[0] * (capacity + 1) for _ in range(n + 1)]

# ② 一行一行、一列一列地把账本填满
for i in range(1, n + 1):              # i 是账本行号:第 i 行表示前 i 箱
    for w in range(capacity + 1):      # 背包当前容量 w
        if weights[i-1] <= w:          # 当前物品的重量小于等于背包当前的容量，说明当前物品可以装进背包
            dp[i][w] = max(dp[i-1][w], dp[i-1][w - weights[i-1]] + values[i-1])     # dp[i-1][w]可以理解成没有放当前物品时的价值，dp[i-1][w - weights[i-1]] 表示不装当前物品前的最大价值，它加上当前物品的价值，即得到装当前物品的最大价值
        else:
            dp[i][w] = dp[i-1][w]

# ③ 答案就在账本"最右下角"那一格
print("最多能装的价值:", dp[n][capacity])
```

(提示:`[[0] * (capacity + 1) for _ in range(n + 1)]` 是**列表推导**的升级版——翻译成人话:**"造一张 (n+1) × (capacity+1) 的二维表,每一格先填 0"**。`dp[i][w]` 这种**两个方括号**叫**二维列表的下标**——翻译成人话:**"第 i 行第 w 列的那一格"**，表示前 i 个物品放入容量为 w 的背包中能获得的最大价值。`max(a, b)` 就是**取 a、b 里更大的那个**,这是"账本高手每一笔都挑赚的那笔"的核心动作。这里的 `i` 是**账本的行号**,从 1 数到 n；而 `weights`、`values` 是 Python 列表,下标从 0 开始,所以第 i 行处理的箱子要写成 `weights[i-1]`、`values[i-1]`。)

猜好数字记在心里,等下 I-do 对答案。

## 一句话接主线

从末影龙巢穴出来的那个晚上,史蒂夫靠在营火旁复盘:**三箱矿粉、20 kg 背包、整箱整箱扛**——他明明有机会扛走 100 分的金矿粉,却被"每 kg 最贵的铁"一叶障目,白送了 40 分。他翻出一本旧账本在扉页写:**"以后每做一个选择之前,先把所有能走的小格子画出来,每一格填上『这种小情况下最赚是几』,大问题的答案就在表格最右下角那一格"**。这就是**动态规划(DP)**——**信奥赛里一半以上的 T3、T4 都是它的地盘**:**0-1 背包、最长上升子序列、最优路径、通关最优攻略**——只要能把"大问题 = 几个小问题拼出来"这句话说通,DP 就能把你带到正确答案的面前。

## 从「账本上的每一格」讲起(I-do)

**DP 的核心魔法只有一句话**:**不去回头,也不去推演未来,但把走过的每一种小情况都记下来**——**大问题就是查几本小账本拼出来**。

拿 0-1 背包举例,史蒂夫面对三箱矿粉和 20 kg 背包时,脑子里真正在问的"小问题"其实长成这样:

- **如果只允许从前 1 箱(铁)里选,背包只有 10 kg,最多能装多少?**
- **如果只允许从前 2 箱(铁、金)里选,背包有 20 kg,又最多装多少?**
- **如果前 3 箱都可以选,背包塞满 20 kg,答案是几?**

你发现没有——**这些问题只差两个数字:"允许前几箱"和"背包容量"**。两个数字一组合,就是一个"小情况"。**把所有小情况都算一遍、记在表格里,最后看最右下角那一格——就是答案**。

这张"账本"长这样(**行**表示"允许前 i 箱可以选",**列**表示"背包容量 w"):

```
           w=0    w=10    w=20
i=0 (空)    0      0       0      ← 一箱都没有,谁都装不了
i=1 (铁)    0     60      60      ← 只有铁,容量≥10 就能把 60 拿满
i=2 (金)    0     60     100      ← 多了金,容量 20 时丢掉铁、装金更赚
i=3 (钻)    0     60     100      ← 多了钻,但钻 30 kg 装不下,答案不变
```

**最右下角那一格就是 100 分**——**正是上一课贪心白丢的那 40 分**。

那每一格到底怎么填?翻译成人话:**对第 i 行、容量 w 这一格,史蒂夫手里永远只有两个选项**——

- **选项 A(不拿第 i 箱)**:这箱我偏偏不要——那答案就跟"只允许前 i-1 箱、容量 w"一模一样——也就是**上一行同一列**那格的数字 `dp[i-1][w]`。
- **选项 B(拿第 i 箱)**:**前提是这箱塞得下**(`weights[i-1] <= w`)——塞进去赚了 `values[i-1]`,但背包得给它腾位置——剩下的容量 `w - weights[i-1]` 还能从前 i-1 箱里最多装 `dp[i-1][w - weights[i-1]]` 分——两份加起来:`dp[i-1][w - weights[i-1]] + values[i-1]`。

**哪种赚 取哪种**——就是 `max(A, B)`。**这就是动态规划的"转移方程"**——翻译成人话:**"这一格的最优 = 从上一行某几格的最优里挑一个最赚的拼出来"**。

把这个想法变成代码——

```python
weights = [10, 20, 30]
values  = [60, 100, 120]
capacity = 20
n = len(weights)

# ① 建一张"账本":n+1 行、capacity+1 列,先全填 0
dp = [[0] * (capacity + 1) for _ in range(n + 1)]

# ② 一行一行、一列一列地填
for i in range(1, n + 1):                 # i 是账本行号,第 i 行表示前 i 箱
    for w in range(capacity + 1):         # 背包当前容量 w
        # 选项 A:不拿第 i 箱 → 跟"上一行同一列"一样
        not_take = dp[i-1][w]
        if weights[i-1] <= w:
            # 选项 B:拿第 i 箱 → 上一行左边某一格 + 这箱的价值
            take = dp[i-1][w - weights[i-1]] + values[i-1]
            dp[i][w] = max(not_take, take)    # 哪种赚挑哪种
        else:
            dp[i][w] = not_take               # 塞不下,只能不拿

# ③ 答案就在账本最右下角那一格
print("最多能装的价值:", dp[n][capacity])
```

- **① 建账本**——`[[0] * (capacity + 1) for _ in range(n + 1)]` 一步到位,4 行 × 21 列,每格先填 0。**第 0 行**代表"一箱都没有",**第 0 列**代表"背包容量是 0"——这两条"什么都没有"的边界永远是 0,不用动。**边界是 DP 的脚**——站不稳,后面全错。
- **② 一行一行填**——**外层循环管"允许前 i 箱"**,**内层循环管"容量 w"**。**每一格都严格只依赖上一行的两格**(同列的一格 + 左边某一列的一格)——这就是"大问题 = 小问题拼起来"的具体样子。**顺序很重要**:必须先把第 i-1 行填完,才能填第 i 行,就像盖楼得先打地基。
- **③ 查答案**——**最右下角那一格** `dp[n][capacity]` 就是"所有箱子都可以选、背包满 20"的最优答案——**不多不少,一分不差**。

跑一下,输出:

```
最多能装的价值: 100
```

**100 分!** 上一课贪心白丢的那 40 分,这次 DP 一分不少地找了回来。**魔法在哪?** 魔法在于——**DP 把贪心"不敢回头"的那一步,变成了"每一步都把所有可能的小情况全记下来,走到最后一行再查答案"**——它不像贪心那样一股脑冲到底,而是**稳稳当当地把 (n+1) × (capacity+1) 张小账本填满,大问题的答案自然浮出水面**。

## 一起改改看(We-do)

**实验:加一箱末影残骸(15 kg / 90 分),看账本怎么扩展**。DP 最可爱的地方是——**同一张账本的填法,换个输入照样跑**,不像贪心换个秤答案就飞了。来加一箱末影残骸:

```python
# 把末影残骸加进来:15 kg,90 分
weights = [10, 20, 30, 15]
values  = [60, 100, 120, 90]
capacity = 20
n = len(weights)

dp = [[0] * (capacity + 1) for _ in range(n + 1)]
for i in range(1, n + 1):
    for w in range(capacity + 1):
        not_take = dp[i-1][w]
        if weights[i-1] <= w:
            take = dp[i-1][w - weights[i-1]] + values[i-1]
            dp[i][w] = max(not_take, take)
        else:
            dp[i][w] = not_take

print("最多能装的价值:", dp[n][capacity])
```

**先别运行,先预测**——加了这箱 15 kg / 90 分的末影残骸之后,答案会**变大、变小、还是不变**?变大最多能变到几?把答案写在纸上。

想一想可行的整箱组合(20 kg 背包)——

- 单独扛铁:10 kg → 60
- 单独扛金:20 kg → 100 ← 原来的最优
- 单独扛末影残骸:15 kg → 90
- 铁 + 末影残骸:10 + 15 = 25 kg → **超载 ✗**
- 金 + 末影残骸:20 + 15 = 35 kg → **超载 ✗**
- 剩下带钻石的组合都更重,**全部超载**

诶?**加完一轮,最大还是 100**(扛金那箱)。预测时很多人会直觉以为"多了一箱东西答案肯定变大"——**但 DP 不会被这种直觉骗**——它老老实实把每一格填完,最后告诉你:**"最优还是 100"**。

跑一下:

```
最多能装的价值: 100
```

**答案不变,一分不多也不少**。**这正是 DP 的脾气**——**它不预设任何"加东西就赚、换秤就飞"的直觉**,**它只认一句话:"所有小情况算一遍,大问题的答案在表格最右下角"**。你拿贪心对同样这组输入试试——**改用"性价比最高先拿"的贪心**:钻 4、金 5、铁 6、末影残骸 90/15 = **6**——铁和末影残骸的性价比并列第一——先拿铁 10 kg、剩 10 kg,再试末影残骸 15 kg 装不下、金 20 kg 装不下、钻 30 kg 装不下——**又是 60!** 贪心再翻一次车,DP 稳如老狗。

**翻译成人话**:**贪心像"抄近路的赛跑选手"——快,但只在特定赛道上跑得对**;**DP 像"摊开所有地图慢慢填"的制图师——慢一点,但从不迷路**。

**代价是什么?** 账本有多大,DP 就要填多久——(n+1) × (capacity+1) 个格子每格一次 `max`——这就是 DP 的**时间复杂度 O(n × capacity)**——翻译成人话:**"运行的时间大致和两个数字乘起来成正比"**。4 箱 × 21 列 = 84 格,眨眼就填完;但如果 n 到 1000、capacity 到 10 万——那就是 1 亿格——**这时候就得想办法"只记一行账本"来省内存**(叫**滚动数组**,是 DP 第二课的事,今天先按住不表)。信奥赛里 **O(n × capacity)** 这个格式会反复见——下一个月你再看到任何 DP 题,第一反应就该是:**"我的账本是啥?每一格该填啥?转移方程长啥样?"**

## 今天你学会了

- **动态规划(Dynamic Programming,DP)**——翻译成人话:**"不只看眼前,把所有小情况的最优解都记在账本上,大问题 = 查几本小账本拼出来"**。它是贪心翻车题的"严肃升级版"。
- **DP 三件套**:**① 状态**(这一格代表的"小情况"是什么——比如"前 i 箱、容量 w");**② 转移方程**(这一格的答案怎么从前几格拼出来——比如 `max(不拿, 拿)`);**③ 边界**(最初始的那几格怎么填——比如"一箱都没有"永远是 0)。**三件套凑齐,DP 就能写**。
- **0-1 背包的 DP 账本**:**`dp[i][w] = 允许前 i 箱,容量 w 时的最大价值`**——**每一格要么来自"上一行同一列"(不拿),要么来自"上一行左边某一列 + 这箱的价值"(拿),哪个大取哪个**。
- **二维列表**:**`dp[i][w]` = 第 i 行第 w 列的格子**——**`[[0] * 列 for _ in range(行)]`** 一句话造一张二维表。**记住行和列各自代表什么,比记代码重要十倍**。
- **贪心 vs DP 的心智模型**:
  - **贪心**:**一杆秤,一路挑到底**——**快、短、简单,但容易被 0-1 背包这种"要忍住小便宜给大块头留位置"的题骗到**。
  - **DP**:**所有小情况都填一遍账本**——**稳、严、永远对**;**代价是账本有多大、就要填多久(O(n × capacity))**。
- **DP 的脾气**:**不被直觉骗**——加一箱东西不一定变大,换一杆秤也不会跑偏——**它只认账本上的每一格**。

学到这里,你的程序第一次**学会了"把所有小情况都想一遍,再优雅地挑最赚"**——**恭喜你,史蒂夫的背包从此一分都不会白丢了**。

**加分再一步(高难,可选)**:**现在只打印了最大价值——那"到底拿了哪几箱"呢?** 提示——**从 `dp[n][capacity]` 倒着往回走**:**如果 `dp[i][w] != dp[i-1][w]`,说明第 i 箱被拿了**(因为"不拿"的那一格就是上一行同列);**然后 w 减掉 `weights[i-1]`,i 减 1,继续往上追**;**一路追到 i=0,拿过的那几箱就是最优方案**。能自己写出这段"回溯"代码,你已经站在正式信奥赛题的大门口了。
