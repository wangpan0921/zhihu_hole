# 把「合成」变成一台机器：函数——程序员的乐高积木

> 这是《我的世界里学编程》系列的第 6 篇。**上期回顾**：上一课我们给史蒂夫的背包用上了列表，一整排格子整整齐齐、想加就加、想扔就扔。可现在他遇到了新麻烦——每次想合成一把剑，都要**几乎一字不差地重敲一遍代码**，写到手抽筋。这一课，我们要教他造一台**合成台**：投料进去、成品出来，用一次调一次，套路只写一次。这就是程序员最爱的乐高积木——**函数（function）**。目标依旧是通向信息学奥赛，但今天只攻一个点：函数。

## 先猜猜看

老规矩，别急着往下拉。心里先跑一遍，这段代码会打印出什么？

```python
def make_sword(material):
    return material + "剑"

print(make_sword("木"))
print(make_sword("铁"))
print(make_sword("钻石"))
```

（提示：一共三行输出。`def` 是「造一台机器」的意思；`return` 是「机器吐出成品」。)

猜好了吗？我们待会儿揭晓。

## 史蒂夫的新麻烦

有了背包，史蒂夫每天满载而归。可他很快发现——**合成东西这件事，他每次都在做同一件事**。

想造木剑，他写：

```python
material = "木"
weapon = material + "剑"
print("造出了：", weapon)
```

想造铁剑，他又写：

```python
material = "铁"
weapon = material + "剑"
print("造出了：", weapon)
```

想造钻石剑，还得再写一遍——**三段代码几乎一模一样，只有一个字不同**。史蒂夫哀嚎：「有没有办法一次搞定？」

有。今天的主角就是——**函数**。

翻译成人话：**函数就是一台你自己造的「机器」——喂它一份原料，它按固定套路加工，然后吐出成品。用一次调一次，套路只写一次。**

故事线接一下：学会了函数，史蒂夫从「每次都要手工敲一遍」进化成了「造合成台的工匠」。以后他每学会一门手艺，就打包成一台机器摆在基地里，下次直接按一下开关。这就是《我的世界》里合成台、烧炉、酿造台背后的共同思想——**把重复的手艺，凝固成一台永远备用的机器**。

## 造一台你自己的合成台（I-do）

在 Python 里，造一台「合成机器」只要三行：

```python
def make_sword(material):
    return material + "剑"
```

拆开看：

- **`def`**：翻译成人话——**「我要造一台机器！」** 后面跟机器的名字 `make_sword`（造剑）。
- **`(material)`**：这台机器的**投料口**。你每次用它，都要塞一份「材料」进来。`material` 是这份材料的临时名字，只在机器内部有效。这个投料口，程序员管它叫**参数（parameter）**——翻译成人话：**「机器留给你塞东西的洞。」**
- **`return material + "剑"`**：机器加工完后，从**出料口**吐出来的东西。这一步叫**返回（return）**——翻译成人话：**「把成品交回给调用我的人。」**
- **缩进**：`def` 那行结尾有个冒号 `:`，下面所有属于这台机器的代码都要**往里缩四个空格**。这是 Python 用来判断「哪些代码是机器内部的」——就像用篱笆把车间围起来。

造好之后怎么用？**直接叫它的名字，把材料塞进去**：

```python
def make_sword(material):
    return material + "剑"

weapon = make_sword("铁")
print("造出了：", weapon)
```

输出：

```
造出了： 铁剑
```

翻译成人话：**`make_sword("铁")` = 「把『铁』塞进合成台，它吐出『铁剑』，我拿变量 weapon 接住」**。这个「叫机器名字 + 括号 + 投料」的动作，程序员管它叫**调用（call）**——翻译成人话：**「按一下机器开关。」**

前面的猜题答案也顺手揭晓了——三次调用、三次投料，机器兢兢业业吐了三次成品：

```
木剑
铁剑
钻石剑
```

同一段套路，写一次，用三次。这就是函数的意义。

## 多个投料口：合成表也能背下来

真正的合成台不止一个格子。造一把镐子要**两样东西**：镐头 + 木棍。函数也可以有多个参数，用逗号隔开：

```python
def make_pickaxe(head, stick):
    return head + "+" + stick + " → " + head + "镐"

print(make_pickaxe("铁锭", "木棍"))
print(make_pickaxe("钻石", "木棍"))
```

输出：

```
铁锭+木棍 → 铁镐
钻石+木棍 → 钻石镐
```

翻译成人话：**投料口有几个就写几个，喂的时候顺序要对上**——第一份材料对第一个投料口，第二份对第二个。喂错了顺序，产物就变味了。

## return vs print：吐成品，还是自言自语？

这是每个新手都会踩的坑，也是本课最值钱的一句话。

看下面这两台机器：

```python
def craft_A(material):
    print(material + "剑")     # 只是自己喊一嗓子

def craft_B(material):
    return material + "剑"      # 把成品端出来

# 试着用它们的结果
a = craft_A("铁")
b = craft_B("铁")

print("a 拿到了：", a)
print("b 拿到了：", b)
```

输出：

```
铁剑
a 拿到了： None
b 拿到了： 铁剑
```

看懂了吗？

- **`print`** 只是让机器**当场喊一嗓子**，喊完就散了，什么都没端出来。所以 `a` 接了个空气——Python 把它记作 `None`（翻译成人话：**「啥也没有」**）。
- **`return`** 才是**把成品端出来交给你**，你可以拿变量接住、继续拼装、再喂给下一台机器。

一句话记住：**要把东西传下去，就用 `return`；只想吼一嗓子，才用 `print`。** 信奥赛几乎从不用 `print` 装结果，全靠 `return`——这一点现在就打好底子。

## 一起改改看（We-do）

现在换你上。看这段代码，**先预测**输出，再运行验证，最后动手改。

```python
def make_potion(main, extra):
    return "药水（" + main + " + " + extra + "）"

print(make_potion("苦力怕的眼泪", "糖"))
print(make_potion("糖", "苦力怕的眼泪"))
```

**先预测**：两行输出会一样吗？

...

**揭晓**：不一样。输出是：

```
药水（苦力怕的眼泪 + 糖）
药水（糖 + 苦力怕的眼泪）
```

因为**参数是按位置对号入座的**——第一份进 `main`，第二份进 `extra`。顺序一换，成品的字符串就跟着变。真实合成里也一样：钻石在上和木棍在上，做出的东西完全不同。

**该你动手改了**：把 `make_potion` 改成接收**三种材料** `main, extra, bottle`，返回 `"药水（main + extra，装在 bottle 里）"`。调用一次，打印结果。

改完再想一步：如果调用时**只喂两样**，会怎样？运行看看，你会撞见一个新错误 `TypeError: missing 1 required positional argument`——翻译成人话：**「你答应了三份原料，只给了两份，机器罢工了。」** 记住这个错误的样子，将来一定还会遇到。

## 今天你学会了

- **函数 = 自己造的机器**：`def 名字(投料口):` 开头，缩进写内部套路
- **参数（parameter）**：投料口，可以有 0 个、1 个、多个，用逗号分隔
- **返回值 `return`**：把成品**端出去**，让外面接住、继续用
- **`print` ≠ `return`**：一个是喊一嗓子，一个是端出成品。信奥赛全靠 `return`
- **调用（call）**：写函数名 + 括号 + 投料 = 让机器开工，比如 `make_sword("铁")`
- **顺序要对**：多个参数按位置对号入座，喂错顺序结果就不对
- **少喂 / 多喂都会报错**：`TypeError` 就是「投料数量对不上」

有了函数，史蒂夫从此不用重敲同一段代码，只需要多摆几台合成台。这也是往后所有程序的地基——**信奥赛的每一道题，几乎都是「写一个函数解决它」**。

## 课后挑战

**🟢 基础关**

写一个函数 `attack(weapon, damage)`，参数是武器名字和伤害值，返回一句话：

```
用木剑砍了 4 点血
用铁剑砍了 6 点血
用钻石剑砍了 8 点血
```

至少调用 3 次，武器和伤害自己搭配。

> 小提示：数字要拼进字符串里，得先 `str(damage)`，像这样：`return "用" + weapon + "砍了 " + str(damage) + " 点血"`。

**🔴 进阶关**

写一个函数 `total_damage(weapon_damage, hits)`——史蒂夫用某把武器连砍 `hits` 下，每下伤害是 `weapon_damage`，返回**总伤害**。

调用示例：

```python
print(total_damage(6, 3))   # 铁剑砍 3 下 → 18
print(total_damage(8, 5))   # 钻石剑砍 5 下 → 40
```

加分挑战：再写一个函数 `is_dead(hp, dmg)`，返回 `True` 或 `False`——目标扣掉 `dmg` 点血之后是不是死了（血量 ≤ 0）。然后**把两台机器串起来用一次**：一头 20 点血的僵尸，被铁剑（每下 6 点）砍 4 下，还活着吗？

> 小提示：函数可以直接调用另一个函数。`is_dead(20, total_damage(6, 4))` 完全合法——第二台机器的成品，直接喂给第一台。这就是「函数拼函数」的乐趣。
