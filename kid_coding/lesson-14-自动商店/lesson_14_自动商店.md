## 从一坨混在一起的代码开始（I-do）

先看一个「不封装」的版本。**先跑通、再优化**——这是程序员的老规矩。

```python
prices = {"diamond": 8, "iron": 3, "emerald": 10}
cart = ["diamond", "iron", "iron", "emerald"]
paid = 30

# 算总价
total = 0
for item in cart:
    total = total + prices[item]

# 算找零
change = paid - total

# 打印小票
print("=== 自动商店 · 小票 ===")
for item in cart:
    print("  -", item, prices[item], "金")
print("总价:", total, "金")
print("付款:", paid, "金")
print("找零:", change, "金")
```

运行一下，输出长这样：

```
=== 自动商店 · 小票 ===
  - diamond 8 金
  - iron 3 金
  - iron 3 金
  - emerald 10 金
总价: 24 金
付款: 30 金
找零: 6 金
```

对上开头的猜测了没？`8 + 3 + 3 + 10 = 24`，`30 - 24 = 6`——**总价 24，找零 6**。

看着挺好，能跑。**但问题也来了**——

- 想给隔壁那位僵尸客户也算一单？**得把上面的 for 和 print 全部复制一遍**。
- 想在总价之外再加个「满 20 减 2」的活动？**得翻遍整段找到「算总价」那几行**。
- 想让别人接手你的代码？**他得从第一行读到最后一行才知道你在干嘛**。

**翻译成人话**：所有事挤在一个「大房间」里，人一多就乱套。

## 用函数把大房间隔成小间（I-do）

第 6 课学过——**函数就是那台「输入材料出产物」的小机器**。现在我们按**「每件事做一件事」**的原则，把上面这一大坨切成**三台小机器**：

```python
prices = {"diamond": 8, "iron": 3, "emerald": 10}

def total_cost(cart):
    """输入购物车，返回总价"""
    total = 0
    for item in cart:
        total = total + prices[item]
    return total

def make_change(paid, cost):
    """输入付款和总价，返回找零"""
    return paid - cost

def print_receipt(cart, paid):
    """输入购物车和付款,打印一张完整小票"""
    cost = total_cost(cart)
    change = make_change(paid, cost)
    print("=== 自动商店 · 小票 ===")
    for item in cart:
        print("  -", item, prices[item], "金")
    print("总价:", cost, "金")
    print("付款:", paid, "金")
    print("找零:", change, "金")

# 主程序:只剩三行
cart = ["diamond", "iron", "iron", "emerald"]
paid = 30
print_receipt(cart, paid)
```

输出和上一版**一模一样**，但**主程序从十几行缩到了三行**。这就是**函数封装（encapsulation）**——翻译成人话：**把「怎么做」藏进小机器里，主程序只关心「做什么」**。

以后你调用 `print_receipt(cart, paid)`，就像点外卖——你只管说要什么，**不用管厨房是怎么炒的**。

再看看这三台小机器互相之间的关系：

- **`total_cost`**——一台「**购物车 → 总价**」机。里面用了**字典查价（第 11 课）** + **for 遍历（第 3、5 课）**。
- **`make_change`**——一台「**付款、总价 → 找零**」机。里面就一句减法。
- **`print_receipt`**——一台「**购物车、付款 → 小票**」大机器。它**内部又调用了前两台小机器**——**函数可以调用函数**，这就是「搭积木」的关键。

**这就是综合模拟的样子**：老知识点一个没换，只是**被重新组合成一个能独立跑的小系统**。

## 一起改改看（We-do）

现在把上面的完整代码复制一份，我们**只改一个数**——把 `paid = 30` 改成 `paid = 20`：

```python
cart = ["diamond", "iron", "iron", "emerald"]
paid = 20              # ← 只改这一处
print_receipt(cart, paid)
```

**先别运行，先预测**——**总价还是 24**，那**找零**这一行会打印出什么？把答案写在纸上。

……

好了，运行一下：

```
=== 自动商店 · 小票 ===
  - diamond 8 金
  - iron 3 金
  - iron 3 金
  - emerald 10 金
总价: 24 金
付款: 20 金
找零: -4 金
```

**「找零 -4」——** 这可不成话啊！现实里没有商店会「反过来找你负数金币」，玩家钱不够，机器就该**当场拦下、报错**。

这就是**综合模拟**最有意思的地方——**跑通只是第一步，把边角料想清楚才算完整**。修一下 `print_receipt`，让它开门就先检查钱够不够：

```python
def print_receipt(cart, paid):
    cost = total_cost(cart)
    if paid < cost:
        print("金币不够！还差", cost - paid, "金")
        return                          # ← 直接结束这台机器
    change = make_change(paid, cost)
    print("=== 自动商店 · 小票 ===")
    for item in cart:
        print("  -", item, prices[item], "金")
    print("总价:", cost, "金")
    print("付款:", paid, "金")
    print("找零:", change, "金")
```

注意这个新出现的 `return`——它是**函数版的「提前下班」**。**条件一亮，机器直接停机走人**，后面那一大坨打印小票的代码根本不会执行。翻译成人话：**「没通过检查就掉头，后面的活一律不干」**。

再拿 `paid = 20` 跑一遍：

```
金币不够！还差 4 金
```

**同一个函数**，只在开头多加了三行「守门员」，整台商店就从「傻乎乎打印负数」升级成「懂拒绝的老板」。这一小步，就是你从**「会写代码」**走向**「会做程序」**的分水岭。

## 今天你学会了

- **综合模拟**：不学新招式，把学过的**变量 / 条件 / 循环 / 列表 / 字典 / 字符串 / 函数**捏成一个能独立跑的小系统——**信奥赛的高频题型**。
- **函数封装**：把「怎么做」藏进小机器里，**主程序只关心「做什么」**——一堆代码从"大房间"变成"三个小间"。
- **函数可以调用函数**：`print_receipt` 里调用 `total_cost` 和 `make_change`——像搭积木一样叠出复杂功能。
- **`return` 提前下班**：不满足条件直接 `return`，跳过后面所有代码。翻译成人话：**「守门员模式」**，让程序学会「拒绝」。
- **命名即注释**：函数取个像 `total_cost` 这样的名字，别人一眼看懂——**好名字是最便宜、也最有效的注释**。

学到这里，你的程序第一次**长得像一件产品了**——有主程序、有小模块、有边界检查。**恭喜你**——第二阶段·进阶关，就在这台自动商店的叮咚声里，稳稳收官。
