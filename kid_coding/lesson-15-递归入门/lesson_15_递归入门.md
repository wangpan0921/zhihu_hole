## 一句话接主线

自动商店叮咚落幕,史蒂夫背上包、举起火把,第一次踏进真正的洞穴。洞里连着洞、洞连着更小的洞,像一层套着一层的俄罗斯套娃。**手写「进第一层、进第二层、进第三层……」根本写不完——洞有多深他并不知道**。他坐在洞口犯愁,我们凑过去说:**你不用一层层写,让程序「自己叫自己」,一直叫到走不动为止**。这就是**递归**——**信奥赛第三阶段第一件必修的思维武器**。

## 从「打开套娃盒子」讲起

想象你面前放着一个大盒子。你打开一看——里面还是一个盒子。再打开——里面还是一个盒子。开到第五层,才是空的。

如果我叫你写代码「把这套娃拆完」,你可能会想:

```
打开第一个盒子
打开第二个盒子
打开第三个盒子
打开第四个盒子
打开第五个盒子
```

但你**根本不知道有几层**——洞穴里也一样,写死几行行不通。真实的思路其实非常简单,就一句话:

> **拆开当前这个盒子。如果里面还有盒子,就用「同一招」再拆它。**

请注意「用同一招」——这就是**递归**。**一个函数,做一件事,中间发现「里面还是同一件事」,就再叫一次自己**。

## 递归的两条铁律(I-do)

回到今天开场的代码,我把两处关键地方圈出来:

```python
def explore(depth):
    if depth == 0:                # ← ①「底」:不能再往下叫了
        print("到底了,返回")
        return
    print("进入第", depth, "层洞穴")
    explore(depth - 1)            # ← ②「自己叫自己」:往里再走一层
    print("退出第", depth, "层洞穴")

explore(3)
```

- **①「底」(base case,翻译成人话:走到头的条件)**——`if depth == 0`。**没有它,函数就会一直叫自己,永远回不来**——那就是递归里最经典的翻车现场(等下我们亲眼看一次)。
- **②「自己叫自己」(recursive case)**——`explore(depth - 1)`。每叫一次,`depth` 都**往「底」靠近一步**。翻译成人话:**「让盒子越来越小」**,最终必然撞上「底」,任务才有希望结束。

**这两条缺一不可**——**「底」是刹车,「自己叫自己」是油门**。少了刹车会失控,少了油门根本没在往前走。

现在跑一下 `explore(3)`:

```
进入第 3 层洞穴
进入第 2 层洞穴
进入第 1 层洞穴
到底了,返回
退出第 1 层洞穴
退出第 2 层洞穴
退出第 3 层洞穴
```

7 行整整齐齐。仔细看这份输出,你会发现两件很酷的事:

第一,**「进入」的顺序是 3 → 2 → 1**——史蒂夫一步步往里走。
第二,**「退出」的顺序是 1 → 2 → 3**——**最后进的最先出来**,像一叠盘子,后放上去的先拿下来。

**翻译成人话**:**递归天生就是「先钻进去,再原路撤出来」**——去时按 A、B、C 的顺序进,回时就按 C、B、A 的顺序退。这也是为什么它天生适合探洞——**先钻到最深处,再一层层原路撤回**,一格都不落下。

## 一起改改看(We-do)

把上面那段完整代码复制一份,**我们只改一个数**——把最后一行的 `explore(3)` 改成 `explore(2)`:

```python
def explore(depth):
    if depth == 0:
        print("到底了,返回")
        return
    print("进入第", depth, "层洞穴")
    explore(depth - 1)
    print("退出第", depth, "层洞穴")

explore(2)              # ← 只改这一处
```

**先别运行,先预测**——现在屏幕会打印**几行**?分别是什么?把答案写在纸上(或者心里默一遍也行)。

……

好了,运行一下:

```
进入第 2 层洞穴
进入第 1 层洞穴
到底了,返回
退出第 1 层洞穴
退出第 2 层洞穴
```

**5 行**。比刚才少了 2 行——**少的正好是「第 3 层」的那一进一出**。你猜对了吗?

再来一个惊心动魄的实验——**故意把刹车拿掉**,把 `if depth == 0` 那三行整段删掉:

```python
def explore(depth):
    print("进入第", depth, "层洞穴")
    explore(depth - 1)              # ← 永远不停地叫自己
    print("退出第", depth, "层洞穴")

explore(3)
```

**先别运行**——猜一下:程序会一直打印下去吗?

跑一下,你会看到屏幕刷刷刷打印一大串「进入第 -996 层洞穴」「进入第 -997 层洞穴」……最后 Python **自己报警了**:

```
RecursionError: maximum recursion depth exceeded
```

翻译成人话:**「你叫太深了!我记不住这么多层!」** Python 内置了一道保险,大约叫到第 1000 层就会强制刹车——这是**递归里最经典的翻车姿势**,叫**无限递归(infinite recursion)**。以后你写递归,第一件事永远是先问自己:**「我的『底』写了没?会不会跳过去?」**

## 今天你学会了

- **递归(recursion)**:**函数在自己里面又叫了自己一次**——翻译成人话:**「自己叫自己」**。
- **两条铁律**:
  - **底(base case)**——**刹车**。没有它就会无限递归、直接翻车。
  - **自己叫自己(recursive case)**——**油门**。**每叫一次都要更靠近「底」**(本课里就是 `depth - 1`),否则永远到不了头。
- **先进后出**:递归天生「先钻到最深处、再一层层原路撤回」——**去时 A → B → C,回时 C → B → A**——第三阶段的**探洞、迷宫、走地图**全靠这一条。
- **无限递归的报警声**:`RecursionError: maximum recursion depth exceeded`——**下次见到它,先想想是不是忘写「底」了**。

学到这里,你的程序第一次拥有了**「自己叫自己」**的思维方式——这是接下来的**深搜(DFS)、树、图**一路要吃到底的核心思想。**恭喜你,第三阶段·算法关,正式开门迎客**。

## 课后挑战

**🟢 基础关**

写一个函数 `countdown(n)`,效果是从 `n` 一路倒数到 1,每个数打印一行;到了 0 就打印一个「点火发射!」结束。

- 参考调用:`countdown(5)`,期望输出 `5 / 4 / 3 / 2 / 1 / 点火发射!`(每行一个)。
- 提示:**先想「底」——什么时候停?** 再想「自己叫自己」——每次让 `n` 变小一点。

**🔴 进阶关**

递归也可以**在一个函数里叫自己两次**——史蒂夫遇到岔路口,**每一层洞穴都分成左右两条路**。看下面这段:

```python
def explore_forks(depth):
    if depth == 0:
        return
    print("到达第", depth, "层的一个岔口")
    explore_forks(depth - 1)      # 走左边
    explore_forks(depth - 1)      # 走右边

explore_forks(3)
```

- 先**手算一下**:`explore_forks(3)` 会打印几行?(提示:想想每层各有几个岔口——1、2、4……总共呢?)
- 再运行验证。你会亲眼看到——**每加深一层,岔口数量就翻一倍**。这就是「指数爆炸」,也是我们后面第 21 课「大 O 复杂度」的开胃菜。
