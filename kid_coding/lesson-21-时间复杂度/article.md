# 大 O 是什么？为什么会超时：史蒂夫的仓库差点查到天亮

> 这是《跟着史蒂夫，从零打通信奥赛之路》系列的第 21 篇。我们会把《我的世界》里的生存任务变成能运行的 Python 程序，再一步步走向信息学奥赛。**上期回顾**：上一课我们亲手写了冒泡排序和选择排序，发现它们都要用两层循环反复比较；今天就来查清楚，为什么有些代码一眨眼跑完，有些代码却会慢到“超时”。

## 先猜猜看

史蒂夫要检查仓库里的箱子。下面两支巡逻队面对 `5` 个箱子，各会检查多少次？先别急着运行，把答案写在纸上。

```python
chests = 5

team_a_steps = 0
for i in range(chests):
    team_a_steps += 1

team_b_steps = 0
for i in range(chests):
    for j in range(chests):
        team_b_steps += 1

print("A 队检查次数：", team_a_steps)
print("B 队检查次数：", team_b_steps)
```

A 队只有一层循环，每个箱子看一次，所以检查 `5` 次。B 队每到一个箱子，都要再和全部 `5` 个箱子打一次招呼，所以检查 `5 × 5 = 25` 次。

要是箱子从 `5` 个增加到 `1000` 个呢？A 队检查 `1000` 次，B 队却要检查 `1000000` 次。箱子只是多了，B 队的工作量却像苦力怕连锁爆炸一样鼓了起来。

## 一句话接主线

史蒂夫的自动化基地越造越大，今天他要学会在写代码前估算工作量，免得仓库管理员一直算到僵尸都下班。

## 游戏场景：比赛只给你一点时间

信奥赛的每道题都有一个**时间限制**。翻译成人话：**程序必须在裁判规定的几秒内交出答案，磨蹭太久就算失败。**

程序超过这个限制，叫做**超时**。翻译成人话：**答案也许能算对，但裁判等不及，直接判这一关没通过。**

那是不是拿秒表测一次就行？不一定。同一段代码，在新电脑和旧电脑上用时可能不同。我们更关心的是：当箱子越来越多，代码的工作量会怎么长大。这种增长速度叫做**时间复杂度**。翻译成人话：**不纠结电脑跑得有多快，只看任务变大时，程序要多忙多少。**

箱子的数量通常记作 `n`，它叫做**输入规模**。翻译成人话：**这次任务一共要处理多少东西，比如多少个箱子、多少块矿石或多少格地图。**

## I-do：给三种仓库任务数数

**第一种：拉一次总闸**

```python
chests = 1000
steps = 0

steps += 1
print("拉下仓库总闸，操作次数：", steps)
```

无论仓库里有 `10` 个还是 `1000` 个箱子，拉总闸都只做一次。这类工作写作 **O(1)**。翻译成人话：**任务再大，我也只做固定几步。**

**第二种：每个箱子巡逻一次**

```python
chests = 1000
steps = 0

for i in range(chests):
    steps += 1

print("逐个巡逻，检查次数：", steps)
```

箱子有多少个，就检查多少次。这类工作写作 **O(n)**。翻译成人话：**任务变成两倍，工作量也大约变成两倍。**

**第三种：让每个箱子和所有箱子配对检查**

```python
chests = 1000
steps = 0

for i in range(chests):
    for j in range(chests):
        steps += 1

print("两两检查，检查次数：", steps)
```

外层循环跑 `n` 次，每次里面又跑 `n` 次，总工作量就是 `n × n`。这类工作写作 **O(n²)**。翻译成人话：**任务变成两倍，工作量可能变成四倍；任务变成十倍，工作量可能变成一百倍。**

`O(1)`、`O(n)` 和 `O(n²)` 里的 `O`，合起来叫做**大 O 表示法**。翻译成人话：**给算法的增长速度贴一张标签，让我们不用真的跑到天荒地老，也能判断它大概扛不扛得住。**

这里的**算法**，翻译成人话：**为了解决一个问题而设计的一套明确步骤。** 大 O 关注的是数据变大后的主要趋势，所以 `n + 3` 通常记作 `O(n)`，`2 × n² + n` 通常记作 `O(n²)`。那几个固定数字不会改变“直线长大”还是“平方长大”的大方向。

还记得上一课的冒泡排序吗？两层循环会做很多次比较，所以它通常是 `O(n²)`。数据很少时，它和现成的 `sort()` 都快得像一眨眼；数据很多时，差距才会露出獠牙。**慢算法**，翻译成人话：**小任务看不出问题，任务一大，工作量就涨得特别凶。** **快算法**，翻译成人话：**面对更大的任务，工作量仍然增长得比较克制。**

## 一起改改看（We-do）

回到开头的两支巡逻队。现在只改一处：把箱子数量从 `5` 改成 `10`。

```python
chests = 10

team_a_steps = 0
for i in range(chests):
    team_a_steps += 1

team_b_steps = 0
for i in range(chests):
    for j in range(chests):
        team_b_steps += 1

print("A 队检查次数：", team_a_steps)
print("B 队检查次数：", team_b_steps)
```

**先预测**：箱子从 `5` 个变成 `10` 个，也就是变成两倍。A 队和 B 队的检查次数分别会变成原来的几倍？

再运行代码揭晓：A 队从 `5` 次变成 `10` 次，是原来的两倍；B 队从 `25` 次变成 `100` 次，是原来的四倍。这就是 `O(n)` 和 `O(n²)` 最值得记住的区别。

把 `chests` 再改成 `100` 也可以。先预测，再运行。你会看到 A 队检查 `100` 次，而 B 队已经检查 `10000` 次。

## 今天你学会了

- **时间限制**：裁判最多愿意等程序运行多久。
- **超时**：程序没在规定时间内完成，答案再有希望也拿不到这一关的分数。
- **输入规模 `n`**：程序这次要处理的数据有多少。
- **时间复杂度**：观察输入变大时，工作量怎样增长。
- **O(1)**：输入再大，工作量大致不变。
- **O(n)**：输入变成两倍，工作量大约也变成两倍。
- **O(n²)**：输入变成两倍，工作量可能变成四倍。
- **大 O 表示法**：用一张简洁标签描述算法的增长速度。

大 O 不是精确的秒表，也不是看到两层循环就永远判死刑。它是一副望远镜：数据还没变得巨大时，就帮你提前看见代码会不会堵车。

**🟢 基础关（You-do）**

补全你的“算法工作量表”。运行下面的程序，观察 `n` 依次变成 `10、100、1000` 时，`O(n)` 和 `O(n²)` 的次数怎样变化。然后不用运行，预测 `n = 10000` 时的两个答案。

```python
sizes = [10, 100, 1000]

for n in sizes:
    linear_steps = n
    square_steps = n * n
    print("箱子：", n, "O(n)：", linear_steps, "O(n²)：", square_steps)
```

**🔴 进阶关（You-do）**

下面的程序用两层循环寻找重复物品。它能正确运行，但最坏时要做接近 `O(n²)` 次比较。请试着只用一层循环和一个 `set` 改写它，让检查过程接近 `O(n)`。

`set` 叫做**集合**。翻译成人话：**一个不会重复收纳物品、还能很快回答“这里面有没有它”的特殊背包。**

```python
items = ["煤炭", "铁锭", "金锭", "钻石", "铁锭"]
found = False

for i in range(len(items)):
    for j in range(i + 1, len(items)):
        if items[i] == items[j]:
            print("发现重复物品：", items[i])
            found = True
            break
    if found:
        break

if not found:
    print("没有重复物品")
```

小提示：先创建 `seen = set()`；每拿到一件物品，先用 `item in seen` 检查，再用 `seen.add(item)` 收进去。
