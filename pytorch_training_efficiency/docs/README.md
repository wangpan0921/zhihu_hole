# 文章发布队列

本系列使用独立的文章队列，不与项目根目录下的 `docs/pending` 混用。

```text
draft/      新生成、人工检查中的文章
pending/    人工检查通过，等待每天 21:00 发布的文章
published/  知乎专栏和公众号都发布成功后的归档文章及元数据
```

人工审核通过后，将文章从 `draft/` 移动到 `pending/`：

```bash
mv draft/文章.md pending/
```

不要直接把文章放进 `published/`。归档脚本只有在两个平台都成功并写入元数据后才会移动源文件。

## 发布前检查

- 第一行是文章标题（`# 标题`）；
- 命令、路径和版本信息不包含本机敏感信息；
- 代码块、表格、列表和图片已经人工检查；
- 文章已经通过对应周次的验收标准；
- 文章文件名和内容顺序符合系列发布顺序。

### 知乎图片

文章中的本地图片可以直接写成相对 Markdown 文件的路径，例如：

```markdown
![训练流程](./images/training-flow.png)
```

知乎专栏发布器会在发布前逐张上传本地图片，并把正文中的引用替换成知乎图片 CDN 地址。上传成功的地址保存在同目录的 `.zhihu.images.json` 缓存中，重试发布时会复用缓存；原始 Markdown 不会被改写。图片不存在、上传失败或上传后无法清理临时节点时，发布会停止，不会点击最终发布按钮。

## 每晚 21:00

安装系列专用 cron 后，每天最多处理 `pending/` 中最早的一篇文章。它会先尝试知乎专栏，再尝试公众号图文；任一平台失败都不会归档源文件，下一次会根据已经写入的元数据继续未完成的平台。

公众号现有自动化入口负责发布图文消息。公众号后台若要求额外把文章加入“训练效能工程成长记录”合集，需要在后台完成该动作，或后续根据实际后台 DOM 增加专门的合集选择步骤；配置中的合集名称会写入发布元数据，便于核对。
