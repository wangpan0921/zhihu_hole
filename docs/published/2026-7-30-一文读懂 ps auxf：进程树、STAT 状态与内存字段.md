# 一文读懂 `ps auxf`：进程树、STAT 状态与内存字段详解

排查 Linux 进程时，`ps auxf` 是一个非常实用的命令。它不仅能列出系统中的进程，还会用树形结构展示父子关系，方便我们追踪一个服务启动了哪些子进程。

这条命令可以拆成四个 BSD 风格的选项：

```text
ps a + ps u + ps x + ps f
```

> Linux 的 `ps` 支持多种选项风格。BSD 风格的选项通常不带连字符，例如 `auxf`；Unix 风格的选项通常带连字符，例如 `-ef`。两种风格可以实现相近的效果，但选择规则和输出格式并不完全相同。

## `a`、`u`、`x`、`f` 分别表示什么

### `a`：显示其他用户的终端进程

默认情况下，`ps` 通常只显示与当前用户和当前终端相关的进程。`a` 会放宽“仅当前用户”的限制，显示与终端关联的其他用户进程。

单独使用 `a` 时，通常仍看不到没有控制终端的守护进程，这正是 `x` 的作用。

### `u`：使用面向用户的详细格式

`u` 会显示用户名、CPU 占用、内存占用等信息。常见字段如下：

```text
USER PID %CPU %MEM VSZ RSS TTY STAT START TIME COMMAND
```

### `x`：包含没有控制终端的进程

`x` 会放宽“必须关联终端”的限制。`systemd`、Nginx、MySQL 等后台服务通常没有控制终端，因此查看系统服务时一般需要带上 `x`。

`a` 与 `x` 组合后，就能看到系统中不同用户、有终端和无终端的进程。

### `f`：以树形结构显示父子关系

`f` 是 `forest` 的缩写，它会在命令列中绘制 ASCII 树，让父进程和子进程的关系一目了然。

这也是 `ps aux` 与 `ps auxf` 的主要区别：

- `ps aux`：平铺显示进程。
- `ps auxf`：以进程树显示父子关系。

需要注意，`f` 是小写字母；大写 `F` 是另一个选项，含义不同。

## 输出字段详解

一段典型的输出如下：

```text
USER        PID %CPU %MEM    VSZ   RSS TTY      STAT START   TIME COMMAND
root          1  0.0  0.3 168420 12340 ?        Ss   08:00   0:02 /sbin/init
```

| 字段 | 含义 |
| --- | --- |
| `USER` | 运行进程的用户 |
| `PID` | 进程 ID |
| `%CPU` | 进程的 CPU 使用率 |
| `%MEM` | RSS 占系统物理内存总量的百分比 |
| `VSZ` | 进程的虚拟地址空间大小，单位通常为 KiB |
| `RSS` | 当前驻留在物理内存中的页面总量，单位通常为 KiB |
| `TTY` | 控制终端；`?` 表示没有控制终端 |
| `STAT` | 进程状态及附加属性 |
| `START` | 进程启动时间或日期 |
| `TIME` | 进程累计使用的 CPU 时间 |
| `COMMAND` | 启动命令；`f` 会在这一列绘制树形分支 |

## 进程树是什么样的

以 Nginx 为例，输出可能类似下面这样：

```text
nginx  1234  0.0  0.1  89000  5432 ?  S  10:00  0:00 nginx: master process
nginx  1235  0.0  0.1  89400  6120 ?  S  10:00  0:00  \_ nginx: worker process
nginx  1236  0.0  0.1  89400  6090 ?  S  10:00  0:00  \_ nginx: worker process
```

其中，`\_` 是 `f` 生成的分支标记。两个 worker 进程缩进在 master 进程下方，说明它们是 master 的子进程。

如果更习惯 Unix 风格的选项，可以使用下面的命令查看层级关系：

```bash
ps -ef --forest
ps -efH
```

它们都能展示进程层级，但字段格式和树的呈现方式与 `ps auxf` 不完全相同，因此不能视为严格等价。

## `STAT` 字段详解

`STAT` 的第一个字符表示进程的主要状态，后续字符表示附加属性。因此，实际输出中经常会看到 `Ss`、`Ssl`、`S+` 等组合。

### 主要状态

| 状态 | 英文 | 含义 |
| --- | --- | --- |
| `R` | Running | 正在运行，或者已经就绪、正在等待 CPU 调度 |
| `S` | Interruptible Sleep | 可中断睡眠，正在等待某个事件，可以被信号唤醒 |
| `D` | Uninterruptible Sleep | 不可中断睡眠，通常正在等待磁盘、NFS 等 I/O 操作 |
| `T` | Stopped | 被作业控制信号暂停，例如按下 `Ctrl+Z` |
| `t` | Tracing Stop | 被调试器跟踪并暂停 |
| `Z` | Zombie | 子进程已经退出，但父进程尚未读取它的退出状态 |
| `I` | Idle | 空闲的内核线程 |
| `X` | Dead | 已消亡的进程，通常不会在输出中看到 |

### 附加标识

| 标识 | 含义 |
| --- | --- |
| `s` | 会话首进程（session leader） |
| `l` | 多线程进程 |
| `+` | 位于前台进程组 |
| `N` | 较低优先级，nice 值大于 0 |
| `<` | 较高优先级，nice 值小于 0 |
| `L` | 部分内存页被锁定在物理内存中 |

常见组合可以这样理解：

- `Ss`：可中断睡眠状态的会话首进程。
- `Ssl`：可中断睡眠、会话首进程，并且包含多个线程。
- `S+`：可中断睡眠，位于前台进程组。
- `Dl`：不可中断睡眠，并且包含多个线程。
- `Z+`：僵尸进程，位于前台进程组。

### 三种需要留意的状态

#### `Z`：僵尸进程

子进程退出后，父进程需要通过 `wait()` 等系统调用读取其退出状态。如果父进程迟迟不处理，子进程就会成为僵尸进程。

僵尸进程的大部分资源已经释放，但仍会占用一个进程表项和 PID。偶尔出现后很快消失通常没有问题；如果数量持续增长，就要检查父进程是否正确回收了子进程。

#### `D`：不可中断睡眠

`D` 状态常见于磁盘故障、NFS 断连或存储 I/O 长时间阻塞。此时即使发送 `SIGKILL`，信号通常也只能保持待处理状态；进程需要先从内核调用中返回，才能处理信号并退出。

因此，排查重点应放在磁盘、挂载点、NFS 和 I/O 状态，而不是反复执行 `kill -9`。

#### `T`：暂停状态

在终端中按下 `Ctrl+Z` 后，前台进程通常会进入 `T` 状态。可以使用 `fg` 将它恢复到前台，或使用 `bg` 让它在后台继续运行。

## `VSZ`、`RSS` 与 `%MEM` 的区别

### `VSZ`：虚拟地址空间大小

`VSZ`（Virtual Size）表示进程虚拟地址空间的总大小，其中可能包括：

- 程序代码、堆和栈；
- 动态链接库；
- 内存映射文件；
- 已分配但尚未真正驻留到物理内存的页面；
- 已被换出的页面。

因此，`VSZ` 很大并不等于进程实际占用了同样多的物理内存。可以把它理解为进程当前拥有的“虚拟地址空间清单”。

### `RSS`：驻留内存大小

`RSS`（Resident Set Size）表示进程当前驻留在物理内存中的页面总量，不包含已经换出到 Swap 的页面。

不过，RSS 也不能简单理解为进程独占的物理内存，因为它包含共享库等共享页面。多个进程的 RSS 直接相加，会重复计算这些共享页面，从而高估总内存消耗。

### `%MEM`：物理内存占比

`%MEM` 大致按下面的方式计算：

```text
%MEM = RSS / 系统物理内存总量 * 100%
```

它基于 RSS，而不是 VSZ。这里的分母是系统物理内存总量，不是 `free` 命令中的“可用内存”。

### 三个字段对比

| 字段 | 全称 | 核心含义 | 是否包含共享页面 |
| --- | --- | --- | --- |
| `VSZ` | Virtual Size | 虚拟地址空间总量 | 包含映射到进程地址空间的共享区域 |
| `RSS` | Resident Set Size | 当前驻留在物理内存中的页面总量 | 包含，因此跨进程相加会重复统计 |
| `%MEM` | Memory Percentage | RSS 占系统物理内存总量的比例 | 继承 RSS 的统计特点 |

在 `top` 命令中，`VIRT` 基本对应 `ps` 的 `VSZ`，`RES` 基本对应 `RSS`。

## 为什么还需要看 PSS

PSS（Proportional Set Size，按比例分摊的驻留内存）会把共享页面按共享进程数进行分摊。例如，一块 10 MiB 的内存由两个进程共享，那么每个进程的 PSS 各计入 5 MiB。

因此，估算一个进程或一组进程的实际内存成本时，PSS 通常比 RSS 更有参考价值。可以使用 `smem` 查看：

```bash
smem -p
```

也可以从 `/proc/1234/smaps_rollup` 中读取 PID 为 1234 的进程汇总数据：

```bash
grep -E '^(Rss|Pss):' /proc/1234/smaps_rollup
```

> 部分较新的 `ps` 版本也支持 `ps -eo pid,user,rss,pss,command`，但不同系统的支持情况可能不同。

## 常用排查命令

```bash
# 按父子关系查看所有进程
ps auxf

# 查看 Nginx 进程，并避免把 grep 本身算进去
pgrep -a nginx

# 查看僵尸进程
ps aux | awk '$8 ~ /^Z/'

# 显示所有线程
ps -eLf

# 按 RSS 从高到低排序
ps aux --sort=-rss

# 持续观察指定进程的 RSS 和 VSZ
watch -n 2 'ps -o pid,rss,vsz,%mem,command -p 1234'
```

## 总结

- `a` 和 `x` 放宽进程选择范围，`u` 提供详细字段，`f` 展示父子关系。
- 排查进程状态时，重点关注 `STAT` 中的 `Z`、`D` 和 `T`。
- VSZ 是虚拟地址空间大小，不能直接当作物理内存占用。
- RSS 表示驻留内存，但包含共享页面；跨进程汇总时更适合参考 PSS。
- 判断内存是否持续增长时，应观察一段时间内的 RSS 或 PSS 变化，而不是只看某一时刻的数值。
