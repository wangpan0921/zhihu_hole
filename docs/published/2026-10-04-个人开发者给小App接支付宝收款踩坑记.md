# 个人开发者接支付宝收款，我踩了很多坑

起因很简单：我做了个可以显示秒的安卓悬浮时钟小工具，想做成"免费试用 7 天、之后 1 块钱永久解锁"。目标朴素——**能在生产环境用支付宝收到这 1 块钱**。真正做下来才发现，"个人开发者、无营业执照、还想自动解锁"这三件事凑一起，路比想象中绕。这篇把全过程和踩的坑按时间线捋一遍，供同样想给个人小工具接收款的朋友避雷。

## 一、先撞墙：微信/支付宝的 App 支付，个人接不了

最初的朴素想法是直接接微信或支付宝的 App 支付 SDK。结论很快清晰：

- **官方 App 支付需要商户号，而商户号需要企业/个体工商户资质**。个人拿不到。
- 个人收款码能收钱，但**没有到账回调**，没法让程序自动确认、自动解锁，只能人工对。
- 第三方"免签约/码支付"那类，多是灰产，封号和资金风险都大，直接否掉。

于是第一轮结论：要"自动解锁 + 无人工"，就绕不开"商店内购 / 资质+服务器 / 官方某种个人收款"三选一。

## 二、转机：支付宝 2026 年的"AI 收款"支持个人实名直签

真正的转机是支付宝新上的 **AI 应用收款（Vibe Pay）**：个人实名即可签约、无需营业执照、钱进个人账户，提供下单、异步通知、交易查询一整套官方接口。对"个人开发者 + 小额收款"这个场景，这是目前最正规、最省心的路子——比第三方聚合支付合规太多。

它支持 App 支付（`alipay.trade.app.pay`）：**服务端用私钥加签生成 `orderStr`，客户端用 SDK 调起支付宝，支付结果以服务端收到的异步通知/主动查单为准**。

## 四、准备支付页截图
为了准备支付页截图，我使用支付宝沙箱跑通了测试流程。

什么是支付宝沙箱？就是解决应用未跑通生产支付流程前，调试支付流程的一个沙箱环境。使用支付宝测试账号密码完成一次支付流程。沙箱工具下载地址：https://open.alipay.com/develop/sandbox/tool

手机安装支付宝沙箱工具，启动第三步里 Agent 自动生成的服务端代码，
.alipay-sandbox.json


### 4.1 准备环境

- 使用 Android 真机并开启 USB 调试；电脑已安装 `adb`、Python 3 和 JDK 17 或更高版本。
- 手机与电脑连接同一个局域网，关闭会阻断局域网访问的 VPN 或代理。我测试时笔记本使用了手机开启的热点。
- 项目根目录已有 `.alipay-sandbox.json`。是 Agent 自测时自动生成，该文件含沙箱密钥和测试账号。
- 安装 Android 沙箱版支付宝。官方入口：
  `https://mdn.alipayobjects.com/sandboxsys/afts/img/_itHRrdOD9oAAAAAAAAAAAAADgSLAQBr/original`
  。如果入口无法打开，前往 `https://open.alipay.com/develop/sandbox/tool` 按页面指引安装。
- 用本项目沙箱配置对应的买家测试账号登录沙箱版支付宝。付款时使用对应的沙箱支付密码，不要使用真实支付宝账号。这些账号密码都在 `.alipay-sandbox.json` 里。
- Debug APK 会显式调用支付宝 SDK 的 `EnvUtils.setEnv(EnvUtils.EnvEnum.SANDBOX)`；必须重新编译并安装修改后的 APK。若仍安装旧 APK，沙箱订单串会被在线环境处理并提示“商家订单参数异常”。

### 4.2 找到电脑的局域网 IP

Linux 下执行：

```bash
hostname -I
```

选择与手机同一网段的地址，例如 `192.168.1.23`。先记为 `<电脑局域网IP>`。

Windows 打开 PowerShell 或 CMD，执行：

  ipconfig

  找到当前正在使用的网络适配器：

  - 使用 Wi-Fi：查看“无线局域网适配器 WLAN”
  - 使用网线：查看“以太网适配器”

  其中的“IPv4 地址”就是局域网 IP，例如：

  IPv4 地址 . . . . . . . . . . . . : 192.168.1.23

  不要选择以下适配器的地址：

  - vEthernet
  - WSL
  - VMware / VirtualBox
  - VPN
  - 已断开连接的适配器

### 4.3 配置真机访问 FastAPI

打开 `app/build.gradle.kts`，把 `buildTypes.debug` 内的地址改为电脑的局域网 IP：

```kotlin
buildConfigField(
    "String",
    "PAYMENT_API_BASE_URL",
    "\"http://<电脑局域网IP>:8000/\""
)
```

例如：

```kotlin
buildConfigField("String", "PAYMENT_API_BASE_URL", "\"http://192.168.1.23:8000/\"")
```

这里只改 `debug` 配置。本地 HTTP 仅对 Debug 构建开放，Release 必须使用公网 HTTPS 地址。

### 4.4 启动 FastAPI

在项目根目录执行：

```bash
python3 -m venv .venv
./.venv/bin/python -m pip install --upgrade pip
./.venv/bin/python -m pip install -r requirements.txt
# 纯标准库服务，用 FC_SERVER_PORT 指定端口（默认 9000）
FC_SERVER_PORT=8000 ./.venv/bin/python -m server.fc_bootstrap
```

保持这个终端运行。另开一个终端，在电脑上检查：

```bash
curl http://127.0.0.1:8000/health
```

应返回：

```json
{"status":"ok"}
```
这里有一个坑：注意端口是否被其他应用占用，如果端口被占用，接口会一直“卡住”，不返回。

再用手机浏览器访问：

```text
http://<电脑局域网IP>:8000/health
```

手机也必须看到相同 JSON。若打不开，检查电脑防火墙是否允许局域网访问 TCP 8000 端口。


### 4.5 构建并安装 5 分钟测试版

使用 `demoDebug`，Debug 才包含上一步配置的局域网 HTTP 地址。

```bash
./gradlew :app:assembleDemoDebug

APK_PATH=$(find app/build/outputs/apk/demo/debug -maxdepth 1 -name '*.apk' -print -quit)
adb install -r "$APK_PATH"
```

## 六、部署踩坑实录：函数计算 + 依赖地狱

决定把服务端放阿里云**函数计算（FC）**，免费额度足够。然后就开始了连环踩坑，每一个都真实发生过：

1. **`ModuleNotFoundError: uvicorn`**：上传了代码但没装依赖——FC 不会仅凭上传就自动装 `requirements.txt`。

2. **代码太大**：把一堆依赖塞进代码目录，超了代码包上限。→ 得用"层(Layer)"。
![6.2](6.2.png)

3. **层不生效**：Python 层的包必须放在 `python/` 子目录下（运行时映射到 `/opt/python`），我一开始把包直接放在 zip 根目录，自然找不到。
![6.1](./6.1.png)

4. **WebIDE 装了、线上还报缺包**：WebIDE 终端是"构建/编辑沙箱"，装完**必须点"部署"**才会进到真正运行的实例。

5. **`libffi.so.6: cannot open shared object file`**：这是最隐蔽的一个。层里连 `alipay-sdk-python`、`pycryptodome` 都装上了，`import Crypto` 也显示 ok，但真正加签时加载它们的**编译扩展**失败——这些 `.so` 链接的 `libffi.so.6` 和 FC 运行时的 libffi 版本对不上。原生依赖的平台/版本错配，在 Serverless 环境里极其常见、又极其难缠。

一个关键排错手法值得记：**加一个临时 `/debug` 接口**，让函数把运行时真实的 `sys.path`、各目录内容、关键 import 的成败直接吐出来。与其在本地猜，不如让线上实例自己说话——这一步直接把问题从"玄学"变成"看得见"。

## 七、最后一公里：那个"商家订单参数异常"

服务端终于能产出 `orderStr`、App 也能调起支付宝了，却弹"商家订单参数异常，请重新发起付款"。两个真实原因：

1. **加签内容漏了 `sign_type`**：支付宝要求对"除 `sign` 外的所有参数（含 `sign_type`）"排序加签，我一开始把 `sign_type` 也排除了。
2. **时间戳时区**：FC 默认 UTC，支付宝要北京时间，差 8 小时。

另外要特别注意**沙箱与正式必须成对**：Release 包走正式支付宝，服务端就得是正式 APPID/密钥/网关；想沙箱联调则两边都用沙箱。错配同样会报"订单参数异常"。

这两处一改、环境对齐，生产环境的 1 块钱终于真实到账、App 自动解锁。全流程打通。

- 还带一个桌面小部件（永久免费），由系统走秒、不占后台。
- 收费也很克制：**免费试用 7 天，之后赞赏/支付 1 元永久解锁本机**，桌面小部件始终免费。

如果你也受够了"全屏时找不到时间"，可以试试。而对独立开发者来说，希望这篇踩坑记能帮你把"收那 1 块钱"的路走短一点。
