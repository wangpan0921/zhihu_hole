# pip 依赖排查：如何反查安装来源，以及未安装时查看某版本依赖要求

排查 Python 依赖时，经常会遇到两个问题：

1. 当前环境里已经有一个包，比如 `gymnasium`、`pyarrow`、`psycopg`，它到底是因为哪个上层包被装进来的？
2. 某个包还没有安装，比如 `ray==2.40.0` 或 `fastapi==0.115.0`，想提前知道它需要哪些依赖、这些依赖的版本范围是什么，应该怎么查？

这两个问题看起来都叫“查依赖”，但实际要用的方法不一样。

尤其要注意一点：**不要只依赖 `pipdeptree` 来回答第一个问题**。`pipdeptree` 能看当前环境里已经展开出来的依赖树，但遇到 `pkg[extra]` 这种 extras 可选依赖时，它不一定能告诉你“这个包是因为哪个 extra 被装进来的”。这类信息要读包元数据。

## 一、为什么不能只用 pipdeptree 反查依赖来源

假设你看到环境里多了一个包：

```bash
python -m pip show gymnasium
```

第一反应可能是用：

```bash
pipdeptree -r -p gymnasium
```

这条命令适合查普通反向依赖：当前有哪些已安装包依赖 `gymnasium`。

但它有一个边界：如果 `gymnasium` 是通过 extra 装进来的，比如：

```bash
python -m pip install "ray[rllib]"
```

那么安装结束后，环境里只会留下：

- `ray` 已安装；
- `gymnasium` 已安装；
- 其他相关依赖已安装。

pip 通常不会保存一条“`gymnasium` 是因为用户安装了 `ray[rllib]` 才进来的”这样的安装历史。`pipdeptree` 看到的是当前环境里已安装包之间的依赖关系，不一定能完整表达“extra 条件依赖”的来龙去脉。

所以更稳的做法是：**扫描当前环境里所有已安装包的元数据，看谁的 `Requires-Dist` 声明过目标包**。

## 二、已安装环境：扫描 Requires-Dist 反查谁声明了它

Python 包安装后，会在 `.dist-info/METADATA` 里记录依赖声明，例如：

```text
Requires-Dist: gymnasium==0.28.1; extra == "rllib"
Requires-Dist: pandas>=1.3; extra == "data"
Requires-Dist: requests>=2.0
```

其中：

- `Requires-Dist` 表示这个包声明了哪些依赖；
- `extra == "rllib"` 表示这条依赖只在安装某个 extra 时生效；
- 没有 `extra == ...` 的通常是普通依赖。

要反查某个已安装包是被谁声明依赖的，可以用下面这个脚本。

脚本里用到了 `packaging` 来解析依赖字符串。如果当前环境没有这个库，先装一下：

```bash
python -m pip install packaging
```

```bash
python - <<'PY'
from importlib.metadata import distributions
from packaging.requirements import Requirement

target = "gymnasium"

for dist in distributions():
    parent_name = dist.metadata.get("Name", "")
    parent_version = dist.version

    for raw in dist.metadata.get_all("Requires-Dist") or []:
        try:
            req = Requirement(raw)
        except Exception:
            continue

        if req.name.lower() != target.lower():
            continue

        marker = str(req.marker) if req.marker else ""
        print(f"{parent_name}=={parent_version}")
        print(f"  {raw}")
        if "extra" in marker:
            print("  note: this dependency is controlled by an extra")
PY
```

如果输出类似：

```text
ray==2.40.0
  gymnasium==0.28.1; extra == "rllib"
  note: this dependency is controlled by an extra
```

就说明：当前环境里的 `ray` 元数据声明过 `gymnasium`，而且这条声明和 `rllib` 这个 extra 有关。

这比 `pipdeptree -r -p gymnasium` 更适合排查 extras 场景。

## 三、这个方法能回答什么，不能回答什么

上面的元数据扫描能回答：

> 当前环境里，哪些已安装包声明自己依赖目标包？

它不能百分百回答：

> 当初那一次 `pip install`，到底是哪条命令把目标包装进来的？

原因是 pip 安装完成后，通常不会保留完整的“安装因果历史”。比如你可能先装过：

```bash
python -m pip install "ray[rllib]"
```

后来又手工装过：

```bash
python -m pip install gymnasium
```

最终环境里只看得到安装结果，看不到完整历史。

所以实际排查时建议这样判断：

1. 先扫描 `Requires-Dist`，找出谁声明依赖目标包；
2. 如果依赖声明里带 `extra == "xxx"`，说明它很可能来自某个 extra；
3. 如果要重现安装过程，用 `pip install --dry-run --report` 对原始安装命令做一次解析。

## 四、未安装时：用 dry-run 看某个版本实际会装什么

第二个问题是：某个包还没装，我想知道某个版本需要哪些依赖，以及这些依赖最终会被解析成什么版本。

最实用的命令是：

```bash
python -m pip install --dry-run --report report.json "ray==2.40.0"
```

如果要查 extra，也要把 extra 写进去：

```bash
python -m pip install --dry-run --report report.json "ray[rllib]==2.40.0"
```

这条命令的含义是：

- 让 pip 正常执行依赖解析；
- 但不真正安装；
- 把解析结果写到 `report.json`。

如果想尽量模拟“干净环境里从零安装”，可以加上 `--ignore-installed`：

```bash
python -m pip install \
  --dry-run \
  --ignore-installed \
  --report report.json \
  "ray[rllib]==2.40.0"
```

否则 pip 会把当前环境里已经安装的包也纳入判断，结果更像“在当前环境上增量安装”，不一定等于新环境从零安装。

生成报告后，可以用下面脚本把将要安装的包和版本打印出来：

```bash
python - <<'PY'
import json
from pathlib import Path

report = json.loads(Path("report.json").read_text())

for item in report.get("install", []):
    meta = item.get("metadata", {})
    name = meta.get("name")
    version = meta.get("version")
    requested = item.get("requested", False)
    mark = " (requested)" if requested else ""
    print(f"{name}=={version}{mark}")
PY
```

这个结果回答的是：

> 在当前 Python 版本、当前平台、当前 pip 配置、当前 index 源和当前约束条件下，pip 打算安装哪些包、选择哪些版本。

这比只看某个包的 `Requires-Dist` 更接近真实安装结果。

如果还想从 `report.json` 里看“目标包自己声明了哪些依赖范围”，可以打印 `requires_dist`：

```bash
python - <<PY
import json
from pathlib import Path

report = json.loads(Path("report.json").read_text())

for item in report.get("install", []):
    if not item.get("requested"):
        continue

    meta = item.get("metadata", {})
    print("# {}=={}".format(meta.get("name"), meta.get("version")))

    requires_python = meta.get("requires_python")
    if requires_python:
        print("Requires-Python: {}".format(requires_python))

    for req in meta.get("requires_dist") or []:
        print("Requires-Dist: {}".format(req))
PY
```

这部分回答的是：

> 这个版本的包本身声明了哪些依赖，以及依赖的版本范围是什么。

而前一个脚本打印的是：

> pip 解析后实际准备安装哪些包、哪些版本。

这两个信息要分开看。

## 五、未安装时：只看某个发行包声明的依赖范围

`pip install --dry-run --report` 适合看“pip 最终会怎么解析”。

但有时你不是想看最终解析结果，而是只想看某个版本的包自己声明了什么依赖范围。例如：

> `fastapi==0.115.0` 本身声明需要哪些依赖？版本要求是什么？

这时可以下载发行包但不安装，然后读取里面的 `METADATA`。

优先下载 wheel：

```bash
mkdir -p /tmp/pkg-meta
python -m pip download --no-deps --only-binary=:all: -d /tmp/pkg-meta "fastapi==0.115.0"
```

然后读取 wheel 里的 `METADATA`：

```bash
python - <<'PY'
from pathlib import Path
from zipfile import ZipFile

wheel = next(Path("/tmp/pkg-meta").glob("*.whl"))

with ZipFile(wheel) as zf:
    metadata_name = next(
        name for name in zf.namelist()
        if name.endswith(".dist-info/METADATA")
    )
    text = zf.read(metadata_name).decode("utf-8", errors="replace")

for line in text.splitlines():
    if line.startswith("Requires-Python:") or line.startswith("Requires-Dist:"):
        print(line)
PY
```

输出可能类似：

```text
Requires-Python: >=3.8
Requires-Dist: starlette<0.39.0,>=0.37.2
Requires-Dist: pydantic!=1.8,!=1.8.1,!=2.0.0,!=2.0.1,!=2.1.0,<3.0.0,>=1.7.4
Requires-Dist: typing-extensions>=4.8.0
Requires-Dist: email-validator>=2.0.0; extra == "standard"
```

这些就是这个发行包元数据里声明的依赖范围。

注意这里看的是“声明要求”，不是 pip 最终选出来的具体版本。比如：

```text
Requires-Dist: starlette<0.39.0,>=0.37.2
```

只说明允许范围是 `>=0.37.2,<0.39.0`，最终安装 `0.37.2`、`0.38.x` 还是别的版本，要由 pip 结合当前环境、依赖冲突、可用发行文件、constraints 文件一起解析。

## 六、如果没有 wheel 怎么办

有些包没有当前平台可用的 wheel，`--only-binary=:all:` 可能失败。

这时有几个选择：

### 1. 让 pip dry-run 解析

```bash
python -m pip install --dry-run --ignore-installed --report report.json "somepkg==1.2.3"
```

如果 pip 能拿到或生成元数据，报告里会包含解析结果。

### 2. 下载源码包看项目配置

```bash
mkdir -p /tmp/pkg-meta
python -m pip download --no-deps -d /tmp/pkg-meta "somepkg==1.2.3"
```

源码包里可能有：

```text
pyproject.toml
setup.cfg
setup.py
```

依赖可能写在：

```toml
[project]
dependencies = [...]

[project.optional-dependencies]
dev = [...]
```

或者传统的：

```python
setup(
    install_requires=[...],
    extras_require={...},
)
```

但源码配置不一定等于最终元数据。有些项目会动态生成依赖，比如根据 Python 版本、平台、构建参数调整依赖。因此能读 wheel 的 `METADATA` 时，优先读 wheel；要看真实安装解析时，优先用 `pip install --dry-run --report`。

## 七、两类查询的推荐命令

| 问题 | 推荐方式 |
|---|---|
| 已安装环境里，目标包被谁声明依赖 | 扫描所有已安装包的 `Requires-Dist` |
| 已安装环境里，目标包是否来自 extra | 看 `Requires-Dist` 里是否有 `extra == "xxx"` |
| 想看普通反向依赖树 | `pip show <pkg>` / `pipdeptree -r -p <pkg>` 可作为辅助 |
| 未安装时，想知道 pip 实际会安装哪些包 | `python -m pip install --dry-run --ignore-installed --report report.json "<pkg>==<version>"` |
| 未安装时，只想看某版本声明的依赖范围 | `pip download --no-deps` 后读取 wheel 的 `.dist-info/METADATA` |
| 想查某个 extra 的依赖 | 命令里写完整：`"<pkg>[extra]==<version>"` |

## 八、小结

这两个问题不要混在一起：

第一个问题是**已安装环境里的反向依赖排查**。如果怀疑某个包是因为 extra 被带进来的，不要只用 `pipdeptree`，应该扫描已安装包元数据里的 `Requires-Dist`，看谁声明了目标包，以及这条声明是否带 `extra == "xxx"`。

第二个问题是**未安装包的依赖预查询**。如果想知道 pip 真正会怎么装，用 `pip install --dry-run --report`；如果只想看某个发行包自己声明的依赖范围，下载 wheel 后读 `METADATA`。

一句话概括：

> 已安装环境查来源，看元数据；未安装版本查安装结果，用 dry-run；查声明范围，读 METADATA。
