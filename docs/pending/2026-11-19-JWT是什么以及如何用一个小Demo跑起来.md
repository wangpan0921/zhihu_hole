# JWT 是什么，以及如何用一个小 Demo 跑起来

登录一个网站后，浏览器为什么可以连续打开多个需要登录的页面？服务器需要在每次请求中确认“你是谁”。JWT（JSON Web Token）就是一种把身份信息放进令牌、再用签名防止篡改的常见方案。

## JWT 解决了什么问题

传统做法是：用户登录后，服务器在内存或 Redis 中保存一个随机的 session id，浏览器之后只携带这个 id。JWT 则把用户标识、过期时间等信息编码进令牌，服务器收到令牌后用密钥验证签名即可，不必为每个登录会话保存一份状态。

一次典型请求大致是：

```text
登录接口校验用户名和密码
        ↓
服务器签发 access token（JWT）
        ↓
客户端在后续请求中携带 Authorization: Bearer <token>
        ↓
服务器验证签名、过期时间和权限，再处理业务
```

JWT 很适合前后端分离、移动 App、微服务之间传递身份信息的场景。它并不是“登录协议”，而是一种令牌格式；登录、权限、刷新和注销仍然需要应用自己设计。

## JWT 长什么样

JWT 通常由三个用点号连接的部分组成：

```text
xxxxx.yyyyy.zzzzz
 头部   载荷   签名
```

以 `HS256` 为例：

1. Header 描述令牌类型和算法，例如 `{"typ":"JWT","alg":"HS256"}`。
2. Payload 是 claims（声明），可以放 `sub`（主体）、`role`（角色）、`iat`（签发时间）、`exp`（过期时间）等信息。
3. Signature 是对前两段做 HMAC-SHA256 后得到的签名，只有持有密钥的一方才能生成正确签名。

前两段只是 Base64URL 编码，任何人都可以解码，所以 JWT **默认不加密**。不要把密码、身份证号、银行卡号等敏感数据放进 payload。真正的安全性来自签名校验和 HTTPS 传输。

常用标准声明包括：

| 声明 | 含义 |
| --- | --- |
| `iss` | 签发者（issuer） |
| `sub` | 令牌代表的主体 |
| `aud` | 受众（哪个服务应该接受它） |
| `exp` | 过期时间，通常必须校验 |
| `nbf` | 在此时间之前不可用 |
| `iat` | 签发时间 |
| `jti` | 令牌唯一 ID，可用于撤销记录 |

## 什么时候适合用

- 前后端独立部署，需要用 HTTP API 传递登录身份。
- 移动端或多个客户端访问同一组 API。
- 微服务之间需要传递用户主体和有限的权限信息。
- 希望 access token 在短时间内自包含，减少每次请求查询 session 的开销。

如果只是一个服务、登录人数不多，传统 session 也很简单可靠。JWT 的“无状态”不是没有代价：签发后很难立刻撤销，payload 变大后每个请求都会携带更多数据，也需要认真处理密钥轮换和客户端存储。

## 一个可以运行的最小 Demo

下面的程序使用 Python 标准库启动 HTTP 服务，使用 `PyJWT` 负责签名和校验。它包含两个接口：登录获得 token，以及携带 token 查看个人资料。

先安装依赖：

```bash
python -m pip install PyJWT
```

保存为 `jwt_demo.py`：

```python
import json
import os
import time
from http.server import BaseHTTPRequestHandler, HTTPServer

import jwt


# 生产环境必须通过密钥管理系统或环境变量注入，不能把真实密钥提交到代码仓库。
SECRET = os.environ.get("JWT_SECRET", "dev-only-change-me-use-a-long-random-secret").encode("utf-8")
USERS = {"alice": {"password": "pass123", "role": "reader"}}


class Handler(BaseHTTPRequestHandler):
    def send_json(self, status, body):
        data = json.dumps(body, ensure_ascii=False).encode("utf-8")
        self.send_response(status)
        self.send_header("Content-Type", "application/json; charset=utf-8")
        self.send_header("Content-Length", str(len(data)))
        self.end_headers()
        self.wfile.write(data)

    def read_json(self):
        length = int(self.headers.get("Content-Length", 0))
        return json.loads(self.rfile.read(length) or b"{}")

    def do_POST(self):
        if self.path != "/login":
            return self.send_json(404, {"error": "not found"})

        body = self.read_json()
        user = USERS.get(body.get("username"))
        if not user or user["password"] != body.get("password"):
            return self.send_json(401, {"error": "用户名或密码错误"})

        now = int(time.time())
        token = jwt.encode(
            {
                "sub": body["username"],
                "role": user["role"],
                "iat": now,
                "exp": now + 300,  # 5 分钟后过期
            },
            SECRET,
            algorithm="HS256",
        )
        self.send_json(200, {"access_token": token, "token_type": "Bearer"})

    def do_GET(self):
        if self.path != "/profile":
            return self.send_json(404, {"error": "not found"})

        header = self.headers.get("Authorization", "")
        if not header.startswith("Bearer "):
            return self.send_json(401, {"error": "缺少 Bearer token"})

        token = header.removeprefix("Bearer ").strip()
        try:
            claims = jwt.decode(token, SECRET, algorithms=["HS256"])
        except jwt.ExpiredSignatureError:
            return self.send_json(401, {"error": "token 已过期"})
        except jwt.InvalidTokenError:
            return self.send_json(401, {"error": "token 无效"})

        self.send_json(200, {"message": "认证成功", "user": claims["sub"], "role": claims["role"]})


if __name__ == "__main__":
    print("JWT demo listening on http://127.0.0.1:8000")
    HTTPServer(("127.0.0.1", 8000), Handler).serve_forever()
```

启动服务：

```bash
JWT_SECRET='local-demo-secret-please-use-32-bytes-or-more' python jwt_demo.py
```

另开一个终端登录。为了方便演示，账号是 `alice`，密码是 `pass123`：

```bash
curl -s http://127.0.0.1:8000/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"alice","password":"pass123"}'
```

响应中的 `access_token` 就是 JWT。把它复制到环境变量，再访问受保护接口：

```bash
export TOKEN='把上一步返回的 access_token 粘贴到这里'
curl -i http://127.0.0.1:8000/profile \
  -H "Authorization: Bearer $TOKEN"
```

你会看到 `认证成功`。如果少改一个字符，服务会返回 `401 token 无效`；等待五分钟后再请求，会返回 `401 token 已过期`。这就是签名校验和 `exp` 校验实际发挥作用的地方。

## 生产环境的几个关键注意点

1. **永远使用 HTTPS**，并把密钥放在 Secret Manager、环境变量或其他密钥系统中；不要写进 Git、日志或前端代码。
2. **固定允许的算法**。校验时显式写 `algorithms=["HS256"]`，不要把 token 里的 `alg` 当作可信输入，也不要为了“兼容”而允许 `none`。
3. **短 access token + refresh token**。access token 可以只活 5～15 分钟，refresh token 单独存储并支持轮换、撤销，降低泄露后的影响范围。
4. **谨慎选择客户端存储位置**。放在 `localStorage` 要考虑 XSS；放在 HttpOnly Cookie 可以降低脚本读取风险，但要配合 CSRF 防护和 `SameSite` 设置。
5. **JWT 不是权限系统**。服务端仍要校验 `aud`、`iss`、角色、资源归属等业务条件；只验证“签名正确”并不等于用户有权访问所有数据。
6. **考虑撤销策略**。登出、改密、封禁账号时，如果必须立即失效，可以维护 `jti` 黑名单、用户 token 版本号，或改用服务端 session。

记住一个简单判断：JWT 适合传递“短期、可验证的身份声明”，不适合承载秘密数据，也不适合替代所有登录和权限设计。
